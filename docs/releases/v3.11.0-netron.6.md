## 🔔 Update indicator fix

The dashboard could keep showing the plain version and never offer an update, even when a newer netron release existed.

- 🚫 **Dev channel ignored on this fork** — this repository publishes no rolling `dev-latest` release. With the "Dev channel" switch on, every check asked GitHub for it, got a 404, and no update was ever shown. The switch is gone from the update dialog and the Nodes page, a saved ON value is ignored, and checks and updates always use the stable release.
- ⚠️ **Failed checks say why** — a failed check used to read as "Panel is up to date". It now shows "Could not check for updates" with the reason (for example GitHub's 60-requests-per-hour limit, a proxy or DNS error) on the version button and in the update dialog, and logs each distinct failure once as a warning.
- 🗄️ **10-minute cache with last-good fallback** — GitHub is asked at most once every 10 minutes; if a refresh fails, the last good answer is kept, and a failing check waits a minute before retrying.
- 🔄 **Automatic re-check** — when the tab becomes visible again, every 30 minutes, and after closing the update dialog, so a release published while the page is open shows up without a reload.

Nothing changes for the per-inbound multiplier, subscriptions or the installer.

### Update

If your panel never showed this update, update from the server's shell:

```bash
x-ui update
```

> [!WARNING]
> Never run the stock upstream installer or updater on a netron server.
